# Web UI 与文件工具（2026-10-22）

本次改造沿用 Jinja2、原生 JavaScript、统一 FileBrowser、原任务队列和数据库。没有引入前端框架，没有数据库迁移，也没有更改 Compose、端口、挂载或启动命令。

## 默认参数与缩略图

设置 → 视频截图与拼图：

- `screenshot_output_mode`：新增设置，默认 `single`，可选 `collage`。文件管理仅一个“生成缩略图”按钮。
- 单图按默认数量输出独立图片；固定拼图按列 × 行取样，自动排布按默认数量取样。提供 3×3、5×4、1×4 预设，原有自定义行列仍可编辑。
- `screenshot_default_sampling` 增加 `timestamps`；新增 `screenshot_default_timestamps`，在设置中填写时间点，服务端校验。
- 原有格式、风格、宽度、片头片尾、目录、HDR/DV 转换、上传开关与上传版本继续生效。图床供应商和凭据仍在图床设置中。
- 拼图从纯画面合成，带原来的媒体信息栏、时间栏与样式；支持 PNG/JPG。自动合成放入配置输出目录下的会话子目录，避免不同会话静默覆盖。
- 自动上传上传当前模式的成品；单图遵守纯画面/装饰版本设置，拼图上传最终拼图。关闭浏览器不影响处理链。
- 任务保存参数快照；失败或取消可重试。已完成且未变化的截图、拼图和上传复用；本地原图始终保留。失败不会静默降低质量。

接口保持原路径。`POST /api/files/screenshots` 增加可选 `output_mode`；省略时保持旧的独立截图行为。新 UI 发送资源和模式，其他参数由服务端默认值解析。截图会话 JSON 保存布局快照、合成结果和任务引用；会话列表增加 `sources` 字段供资源匹配。手动重新合成接口增加可选 `format`（省略仍为原 JPEG 行为）。没有增加数据库表、列或状态。

## 发布资料

发布资料只汇总已有结果，不隐式生成报告、截图或种子。

1. 选择文件或目录，也可从文件工具结果带入。
2. 发布资料中的“搜索作品”默认使用 PT-Gen 豆瓣片名搜索。核对候选年份、季度后选择，直接获取简介、名称、海报和来源链接，不依赖 TMDB 或 IMDb 抓取成功。可切换 TMDB 补充英文名称等资料；批量重命名的共享选片器仍默认 TMDB。也支持手动填写豆瓣/IMDb 链接。IMDb 或其他服务失败时保留资料，提供“按片名查找豆瓣”恢复入口；有人工修改的字段需预览后决定是否替换，空值不清除已有内容。
3. 原始报告和种子按根目录与规范化路径匹配；截图按会话来源匹配，目录只匹配路径边界内的后代，不把 `MediaExtra` 当作 `Media` 的内容。多个报告/种子候选不自动选最新。
4. 历史草稿优先恢复保存的关联 ID；没有同源结果时明确显示缺项。另有显式“手动关联其他已有图片”，保留独立上传图片的用途。
5. 修改标题、简介、资源参数和分类标签，更新发布内容或保存草稿，再复制 BBCode/Markdown/HTML。截图可调整顺序；分类标签需确认。规则缺项允许保存复制，但不能显示就绪。

媒体报告是独立产物，原文不改；发布草稿保存在原发布会话表。影视资料来源、作品标识、目录属性和检查结果使用已有 JSON 字段。切换资源前确认未保存编辑；异步响应有版本保护，不把旧资源结果填入新资源。

## 前端事件与真实接口

| 入口 / 事件 | 复用的处理链 |
| --- | --- |
| 文件工具栏与右键 | FileBrowser `runAction` → `CollageTool.open` / `BiliModules.runFileTool` |
| 生成缩略图 | `/api/files/screenshots` → 原 `screenshot` 任务 → 服务端可选合成及上传 |
| 重截、删除、排序、重新合成 | 原截图会话 item/order/collage 接口；合成沿用 `screenshot_collage` |
| 生成报告 / 制作种子 / 上传 | 原 `/api/release-info/jobs`、`/api/torrents/jobs`、`/api/uploads/jobs` |
| 任务状态、取消、重试、日志 | 原 `/api/tasks` 处理链，保留真实状态与错误 |
| 保存及复制发布资料 | 原 `/api/publish/sessions` 创建/更新与既有三种格式 |
| 选片与资料补充 | 新增只读 `/api/media/ptgen/search?query=片名`；保留原 TMDB 搜索、详情及 `POST /api/media/ptgen`，候选由用户确认 |
| 全局设置 | 原设置 schema、读取、保存、服务端校验与加密机制 |

嵌套文件选择器或预览打开时，原工具节点留在隐藏挂载区，后台完成回调仍能找到原控件；关闭嵌套弹窗后回到原面板。原记录超过最近列表窗口时，按草稿保存的 ID 单独读取报告、种子、截图和海报，防止刷新后丢失关联。


### PT-Gen 搜索与故障恢复

- 服务地址继续填写已有完整信息接口，例如 `http://主机:23333/api/v1/info`，无需另设搜索地址。搜索适配器会使用同一主机、同一路径前缀下的 `/api/v1/search`；旧版 worker 地址使用原 `?search=` 协议。同一份加密的 PT-Gen API Key 用于搜索和信息查询，不向浏览器返回。
- PT-Gen 的服务 API Key 用于访问 PT-Gen 自身，不能使 IMDb 网页抓取获得结构化数据。当前部署的 IMDb 抓取器直接请求网页，不读取 `IMDB_API_KEY`；网页返回空内容时，应用无法补出丢失的 JSON-LD。豆瓣搜索/链接是一条可独立工作的资料来源。
- 搜索返回的不同年份、季度须人工选定，不自动采用首项。上游搜索未启用、失败或没有匹配项时，可以切换 TMDB，或者展开“外部链接、海报与 PT-Gen 原文”，填写豆瓣链接后点击“补充 / 重试简介”。
- 已有 IMDb 草稿不需要删除或重建：点击“补充 / 重试简介”，失败后点击“按片名查找豆瓣”；核对条目和变更字段后继续保存原草稿。
