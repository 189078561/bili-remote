# 发种工作台产品级重建

本轮以用户最终指令为准，替换此前固定三栏方案。工作区仍为 `/opt/bili-remote`，分支 `v2-integration`，HEAD `679b7c7`；不提交、不部署。开始时已有 32 个未提交文件，原始副本保存在忽略目录 `.dev/workbench-product-baseline/`。本轮开始前全量基准为 404 项，第一阶段历史基准为 393 项。

## 信息架构与实际操作

旧结构是常驻文件浏览器、配置与编辑栏、常驻发布预览。新结构是一个随页面滚动的内容工作区：当前正式资源摘要 → 影视身份与命名预览 → 主标题、副标题、简介 → 辅助工具与后台任务。没有发种项目、保存草稿或流程向导。

从文件管理或下载页进入时直接接受原交接上下文，不再打开资源浏览器。点击“更换资源”才显示共享 FileBrowser；勾选仅暂存，点击“使用所选资源”才正式切换。取消面板不提交；有人工编辑时沿用原资源切换确认。

影视名称、名称候选、命名类型、季号、集号、处理范围直接可见。修改后合并短时间内的输入，调用原服务更新只读预览；“确认重命名”仍携带原预览令牌、修订、确认标志和幂等键执行。高级逐文件参数、映射、字幕关联、规则记忆及撤销在“命名详情”中使用原组件。高级结果可以回显在主页面，执行及撤销仍由原高级组件管理。

发布区直接编辑三项实际内容，没有镜像文本或大型嵌套卡片。主标题、副标题沿用自动生成与明确替换人工内容的行为；简介来自资料识别，人工编辑后继续受保护。内容实时交给现有发布组合接口处理。

下方三个工具入口打开缩略图、媒体报告、种子制作面板，保留原截图、拼图、下载、上传、MediaInfo/BDInfo、本地制种、种子下载、添加 qBittorrent、任务重试及产物入口。“预览与复制”单独打开完整发布内容，支持 BBCode、HTML、Markdown，效果/源码切换、完整复制和缺项提示。

## DOM、CSS 与状态边界

已删除旧布局容器 `.wb-layout`、`.wb-files`、`.wb-main`、`.wb-output` 以及多层常驻配置布局。重新构建 `.wb-surface`、`.wb-resource-bar`、`.wb-studio`、`.wb-identification`、`.wb-publishing`、`.wb-tool-launcher` 与五个按需面板。所有原业务挂钩均保留，运行时不复制发布表单、不重新挂载工作台或 FileBrowser。

`workbench.css` 整体按新结构整理，不在旧三栏样式末尾叠加覆盖。共享主题及本地 Lucide SVG 图标直接复用，本轮不修改全局样式和其他四个页面。桌面内容最大宽度 1120px，主工作区保持单列；按需面板最大宽度 860px。手机主体仍按业务顺序排列，面板全屏，主要交互高度至少 44px。桌面导航和移动导航沿用现有实现。

正式状态仍由原 `Workbench` 实例管理；面板控制器仅处理显隐、焦点、背景不可交互和滚动。候选/正式资源、资源 epoch、请求版本、字段编辑版本、人工锁定、上下文修订、改名令牌及有效期、任务所属资源均保留。

新增自动预览调度不执行文件操作；显式点击预览会先处理尚未提交的名称/季集输入。快速连续修改保留最新规则。对同资源的旧识别响应已推进服务端修订、但仍在传输中的情况，只借其修订作为最新输入的重试基础，不把旧响应字段渲染回页面；资源版本变化后不会继续该重试。

`generate`、`compose`、`naming`、`applyRename`、`probe`、`screenshots`、`report`、`torrent`、`upload`、`track`、`refreshTasks`、`applyTask` 等核心方法与本轮开始时逐字一致。变动集中于新视图控制、自动预览调度、识别响应版本协调及高级预览展示。逐文件证据见 `.dev/workbench-product-visual/business-preservation.json`。
