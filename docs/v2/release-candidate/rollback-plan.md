# 发布候选回滚计划

日期：2026-11-11
状态：仅供后续人工预发布/生产操作，本轮未执行任何回滚或生产操作。

## 目标

回滚应恢复已知可用的代码和配置，同时保护用户数据库、任务记录、媒体、下载、截图、报告、torrent 及原工作区未提交修改。不能通过清理工作树来“回滚”。

## 发布前必须记录

1. 当前生产运行版本或镜像摘要。
2. 部署配置版本及安全恢复位置，不复制明文密钥到 Git。
3. 数据库备份/快照标识和恢复演练结果。
4. 当前活动任务、命名批次和 torrent 任务的处置窗口。
5. 新发布源码包路径、SHA-256、文件数和提交 SHA。
6. 预发布验收结论及外部服务阻塞清单。

## 触发条件

- 登录、CSRF 或权限校验回归。
- 文件路径、覆盖、指纹或命名执行安全回归。
- 数据迁移失败、数据库不可用或记录语义异常。
- 旧 API/旧版入口严重不可用。
- 任务队列重复执行、关联错乱、无法恢复或产物丢失。
- 前端关键入口不可用或静态资源严重错误。
- 出现密钥、Cookie、数据库或私有配置泄漏。

## 代码回滚

1. 停止新任务接入，避免更多任务进入问题版本。
2. 保留问题版本日志、错误请求标识和只读诊断信息。
3. 使用发布前记录的上一可用镜像/静态产物/代码版本重新启动，不使用 `git reset --hard` 或 `git clean` 修改用户工作区。
4. 若本轮发布仅改变应用代码，优先回退代码与静态资源；依赖和运行环境未经本轮升级，通常无需回退宿主环境。
5. 若已按仓库方案轮换配置，恢复对应配置版本；凭据由安全存储处理。
6. 重新执行登录、文件只读、旧 API、首页真实数据、任务列表和 worker 健康检查。

## 数据回滚

本轮没有新增数据库迁移，因此常规代码回滚不应需要 schema 回退。若数据库本身损坏或发布后发现数据异常：

- 先停止写入并保全现场。
- 由有权限人员依据发布前快照制定恢复点。
- 明确恢复会影响的下载、任务、审计和规则记录。
- 不以清空数据库或删除媒体代替恢复。
- 不在未确认数据差异前覆盖生产数据库。

## 文件与任务保护

- 不自动反向重命名用户文件；命名撤销使用应用审计记录和显式预览/确认链路。
- 不删除已生成的截图、报告、torrent、下载媒体或临时任务结果，除非用户另行明确要求。
- 对进行中的下载、制种和上传，按后台任务原有控制执行等待、取消或恢复。
- 恢复旧代码后如 hash/torrent 源校验已改变，必须重新制种；不得恢复“源已变化仍可下载旧 torrent”的缺陷。
- 文件权限错误或部分完成状态应保留诊断信息，不静默重试覆盖。

## 验证

回滚后至少检查：

1. 服务健康、登录和 CSRF。
2. 首页真实资源和任务未消失。
3. 文件管理只读浏览、路径安全与旧 API。
4. 未完成任务状态可解释，worker 不重复消费。
5. 设置读取不泄漏凭据。
6. `/legacy` 可访问。
7. 日志无新增异常洪泛。

## 已知修复的回退风险

`7659e48` 增加了 torrent 下载时的源资源一致性检查。若回退到该提交之前，会重新暴露“文件改名后旧 torrent 仍可下载”的风险。生产若必须回退，应优先保留该安全校验的热修复，或明确将受影响 torrent 标记为需要重新制种。
