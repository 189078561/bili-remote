## 隔离预发布步骤

1. 从未修改的发布产物或干净检出创建独立目录，不复用生产数据库和媒体目录。
2. 使用 `.env.dev.example` 或预发布密钥管理系统生成独立配置；不得复制生产密钥和 Cookie。
3. 绑定回环地址及非 8111 端口，使用独立 SQLite、下载、图片、torrent、日志和临时目录。
4. 在预发布环境运行既有初始化/迁移。本轮没有新增 schema 迁移，但仍应验证空库初始化、已有库升级和重复初始化。
5. 完成本目录的功能、媒体、命名、E2E 和外部联调人工清单。
6. 检查旧版 `/legacy`、旧 API、登录/CSRF、文件路径安全、活跃任务状态和设置保存。
7. 检查前端静态资源缓存头、构建一致性和 1024/768/390 等移动断点。
8. 生成预发布验收记录；任何外部服务缺口继续如实标记。

## 生产前置条件

- 预发布环境本地功能全部通过。
- 外部在线服务缺项由有权限人员完成或明确批准延后。
- 浏览器日志无未处理异常，服务日志无密钥、Cookie 或敏感请求泄漏。
- 系统所有者确认活跃下载、重命名、制种任务的处理窗口。
- 已记录当前生产代码版本、配置版本、数据库备份/恢复点和上一可用发布产物。
- 已核验源码包 SHA-256、文件数和安全清单。

## 生产切换建议

1. 暂停新任务接入并等待可安全中断的边界；不强制中断正在写入的媒体操作。
2. 按既有运维流程部署已审阅提交或源码包，不直接在工作区执行破坏性 Git 操作。
3. 由安全存储注入现有生产配置，不把密钥写入报告。
4. 启动后进行登录、首页真实数据、文件浏览、任务抽屉、设置只读、旧版入口和健康检查。
5. 创建一条获准的短测试下载，验证文件管理与工作台交接；不自动向 PT 站点发布。
6. 观察任务 worker、错误率、数据库锁、静态资源和移动端基础操作。
7. 验证完成后恢复新任务接入并记录发布结果。

## 数据库与配置

- 设置 schema 仍使用现有键；真实凭据由部署环境管理。
- 任务和文件记录保持既有语义。

## 停止条件

出现以下任一情况立即停止切换，不在生产现场临时改业务逻辑：

- 未提交工作区存在被覆盖风险。
- 数据迁移结果与备份/基线不一致。
- 活跃任务可能被中断且没有恢复策略。
- 路径安全、人工编辑保护或命名预览出现回归。
- 登录失败、前端资源 404、API 兼容或旧版入口不可用。
- 发现密钥、Cookie 或数据库被写入源码包/日志。

本计划读完不代表已获部署授权。生产变更必须由用户再次明确批准。
